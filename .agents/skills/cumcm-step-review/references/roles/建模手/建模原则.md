
# 建模原则

数学建模的核心不是寻找最复杂的算法，而是把题目中的对象、目标、约束、数据与现实规律组织成一个能够求解、验证和解释的模型。

---

## 一、问题先于算法

拿到题目后，先回答：

| 要素 | 核心问题                            |
| ---- | ----------------------------------- |
| 目标 | 最终需要预测、评价、解释还是决策？  |
| 对象 | 研究的实体、状态和过程是什么？      |
| 数据 | 有哪些观测量，时间/空间范围是什么？ |
| 变量 | 哪些量需要预测、估计或优化？        |
| 约束 | 哪些条件必须满足？                  |
| 关系 | 变量之间依据什么发生联系？          |
| 输出 | 最终需要什么数值、方案或排序？      |

模型从这些信息中产生，而不是从“这道题适合什么算法”开始。

---

## 二、模型必须覆盖题目的关键结构

模型的最低要求是覆盖：

> **题目目标 + 关键约束 + 关键数据 + 决策所需信息**

题目明确要求考虑的因素，必须在模型中真正发挥作用。它可以进入变量、目标函数、约束、参数关系、状态转移或决策规则。

### 报告式与决策式

凡题目要求“考虑、权衡、优化”某个因素 \(X\)，都检查：

> 删除 \(X\) 后，最终决策是否改变？

若只是得到方案后再报告 \(X\) 的数值，属于报告式处理；若 \(X\) 进入目标函数或约束并影响方案选择，才是真正进入模型。

---

## 三、模型复杂度服从问题

| 原则             | 判断                                   |
| ---------------- | -------------------------------------- |
| 先有基线         | 先判断简单、清晰的模型是否已经满足题目 |
| 不为复杂而复杂   | 复杂度应由问题结构、数据和验证要求决定 |
| 不堆模型         | 每增加一个模型都要说明其独立作用       |
| 不堆算法         | 更换求解器不等于模型创新               |
| 不为论文制造创新 | 基线已经充分时，不强行增加复杂结构     |

简单模型不是低级模型，复杂模型也不是天然更优。

一个新增变量、约束或模型若不能解决原模型无法解决的问题，应优先删除。

---

## 四、模型选择必须有“为什么”

模型选择至少回答：

1. 当前问题有什么结构；
2. 候选模型能处理什么结构；
3. 为什么当前模型与题目匹配；
4. 其他明显候选为什么没有采用。

理由应来自问题本身，而不是算法的通用优点。

不要写：

> “XGBoost 具有较高精度，因此采用 XGBoost。”

应说明：

> 数据具有什么特征，模型能够利用什么关系，以及这些关系为什么与当前问题匹配。

模型选择结论不能由最终指标反向包装。应先有选择依据，再通过实验验证选择是否成立。

---

## 五、假设只描述必要的现实理想化

模型假设应说明对现实问题做了什么必要简化。

以下内容不要混入模型假设：

* 题目直接给出的规则和约束；
* 数据整理、标准化、缺失值处理；
* 训练集/测试集划分；
* 随机种子与程序参数；
* 软件和求解器设置。

判断标准：

> 删除题目、代码和数据处理细节后，剩下的内容是否仍然是对现实世界的前提假设？

是，才属于模型假设。

不要为了“假设合理”而制造大量无关假设。

---

## 六、数据事实、模型关系、解释结论分开

建模过程中区分三层：

| 层次     | 示例                                 |
| -------- | ------------------------------------ |
| 数据事实 | \(X\) 与 \(Y\) 的相关系数为 0.82     |
| 模型关系 | 在模型中，\(X\) 进入成本函数         |
| 解释结论 | 在当前假设下，\(X\) 增加会使成本上升 |

数据本身可以描述现象，但不能自动提供因果解释。

没有额外证据时：

> 相关 ≠ 因果
> 指标高 ≠ 原因成立
> 结果稳定 ≠ 模型正确

---

## 七、领域知识应进入模型结构

领域知识不仅用于最后解释结果，更应尝试转化为模型的一部分。

常见形式包括：

| 领域知识      | 模型表达           |
| ------------- | ------------------ |
| 规律或先验    | 正则项、先验分布   |
| 物理/工程限制 | 硬约束、边界条件   |
| 单调关系      | 参数约束、结构约束 |
| 状态演化规律  | 状态方程、转移关系 |
| 网络依赖      | 图结构、邻接关系   |
| 合理区间      | 可行域、结果检验   |
| 领域特征      | 特征工程、损失项   |

优先追问：

> **这个领域规律能不能改变模型，而不是只改变结果解释？**

---

## 八、创新发生在建模层

建模创新优先从以下位置寻找：

| 方向     | 典型改动                         |
| -------- | -------------------------------- |
| 变量设计 | 新增状态量、决策变量、层次变量   |
| 模型结构 | 分层、解耦、耦合、分解           |
| 目标函数 | 显式加入原题中的隐含目标         |
| 约束设计 | 将现实规律转化为可行域           |
| 模型组合 | 建立有实际依赖的串联、嵌套或集成 |
| 评价机制 | 设计更贴合问题本质的指标         |
| 领域知识 | 将领域规律转化为模型结构         |

创新的重点是：

> **改变了什么建模关系，而不是增加了多少算法。**

单纯换求解器、调几个超参数、增加图表或做常规后处理，通常不能作为主要建模创新。

---

## 九、创新必须解决原模型的问题

一个创新候选至少说明：

> **原模型哪里不足 → 改了什么 → 为什么这样改 → 改后解决了什么**

如果只是：

> “加入某算法后效果更好”

但没有说明为什么需要这个改动，创新依据不足。

不要把“大家都会做”的组合直接包装成创新，也不要因为论文需要“创新点”而强行制造改动。

---

## 十、创新必须能够验证

创新不能只写在论文里，必须能够通过实验体现。

优先考虑：

* 基线模型对比；
* 消融实验；
* 参数扰动；
* 替代模型比较；
* 样本外验证；
* 约束可行性检查；
* 稳定性分析。

每项创新至少能够回答：

> 改动后什么发生了变化？

若无法设计合理的验证方式，则降低其创新地位，不要强行包装。

---

## 十一、模型组合要有真实关系

多个模型只有在承担明确、互补的任务时才有组合价值。

| 组合方式          | 要求                             |
| ----------------- | -------------------------------- |
| 串联              | 前一模型输出是后一模型的必要输入 |
| 并联              | 需要比较不同假设或方法           |
| 嵌套              | 一个模型直接进入另一个模型       |
| 主模型 + 验证模型 | 二者职责明确，验证边界不同       |

例如：

> 需求预测 → 库存优化

存在明确的数据依赖。

而：

> 预测 + 聚类 + TOPSIS

如果三个模型只是并列展示、没有共同决策链，就不应仅因数量多而称为复杂模型体系。

---

## 十二、保留有价值的试错

模型选择不是只记录最后采用的模型。

有价值的试错包括：

> 哪些候选被尝试过；
> 为什么不适合；
> 哪个假设被数据否定；
> 哪个创新没有带来预期改善。

淘汰一个明显不合适的方案，本身就是建模证据。

但不需要为了“留下痕迹”保存大量无效实验。

---

## 十三、模型验证针对真正的风险

验证不采用固定模板，而应针对模型最可能失败的地方。

例如：

| 模型风险         | 优先验证        |
| ---------------- | --------------- |
| 参数敏感         | 参数扰动        |
| 预测过拟合       | 样本外 / 回测   |
| 优化结果不稳定   | 多起点 / 多种子 |
| 关键约束可能失效 | 约束回代        |
| 创新贡献不明确   | 消融实验        |
| 异常数据影响大   | 异常值扰动      |
| 多目标权衡敏感   | 权重敏感性      |

验证应回答：

> **模型在什么条件下仍然成立，什么情况下可能失效。**

---

## 十四、模型结论不得超过证据

结论强度与证据匹配：

> 单次实验 → 只能描述当前结果
> 多次重复 → 可以讨论稳定性
> 对比实验 → 可以讨论相对表现
> 样本外验证 → 可以讨论泛化
> 多种独立检验 → 才能更有把握地讨论稳健性

避免仅凭一次结果使用：

> 证明、保证、最优、显著优于、完全适用、首次提出

尤其不要把“指标最好”直接等同于“模型最适合”。

---

## 十五、建模判断的边界

AI 可以负责：

* 整理问题与候选模型；
* 推导公式；
* 检查实现；
* 运行实验；
* 比较结果；
* 暴露模型风险。

涉及以下内容时应保留建模者判断：

* 哪个现实因素应该进入模型；
* 哪种假设可以接受；
* 两种方案之间的实际取舍；
* 结果的现实含义；
* 某项改动是否值得作为创新；
* 论文中应当如何界定贡献。

---

## 十六、建模完成前自检

* [ ] 模型直接回答题目要求
* [ ] 关键目标和约束进入模型
* [ ] 题目要求考虑的因素真正影响决策
* [ ] 模型选择有针对当前问题的依据
* [ ] 没有为了复杂度堆叠算法
* [ ] 假设属于现实问题的必要理想化
* [ ] 数据事实与因果解释没有混淆
* [ ] 领域知识尽可能进入模型结构
* [ ] 每项创新都有明确改动和问题来源
* [ ] 创新能够通过实验验证
* [ ] 模型组合存在真实的数据或逻辑关系
* [ ] 验证针对模型的主要风险
* [ ] 结论强度没有超过证据
* [ ] 删除任何一个新增部分后，都能说明它为什么不能被简单删除

---

## 十七、核心判断

遇到建模困难时，优先问：

> **题目到底要解决什么？**

> **什么因素真正决定答案？**

> **这些因素有没有进入模型？**

> **为什么这样建，而不是直接套一个常见模型？**

> **增加这一部分解决了什么原模型没有解决的问题？**

> **这个改动能不能验证？**

> **模型是否已经复杂到超过问题本身的需要？**

最终目标不是制造“高级模型”，而是形成：

> **问题匹配、结构清楚、关键因素进入模型、创新有依据、结果可验证、结论有边界的模型。**

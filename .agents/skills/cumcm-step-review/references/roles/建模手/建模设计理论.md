# 建模设计理论

## 问题与模型匹配

| 问题结构     | 模型方向                             | 必查条件                           |
| ------------ | ------------------------------------ | ---------------------------------- |
| 约束下求最优 | 线性、整数、非线性、鲁棒或多目标优化 | 变量类型、可行域、目标和约束       |
| 随时间变化   | 时间序列、状态空间、机器学习预测     | 时间顺序、平稳性、外生变量和回测   |
| 多指标排序   | 统计降维、组合赋权、效率评价         | 指标方向、相关性、权重依据和稳健性 |
| 网络关系     | 最短路、网络流、复杂网络             | 节点、边、方向、权重和连通性       |
| 不确定系统   | 概率模型、蒙特卡洛、随机或鲁棒优化   | 分布依据、场景和风险指标           |
| 模式识别     | 聚类、分类、集成学习                 | 标签、样本代表性、数据泄漏和验证集 |

## 设计原则

1. **充分性**：覆盖题目目标、关键约束和关键数据。
2. **可证伪性**：预先定义会让模型失败的检验。
3. **可实现性**：公式、算法与 Python/MATLAB 工具一致。
4. **可追溯性**：参数、阈值和假设都有来源。
5. **创新性**：避免直接套用常见简单模型；创新点必须能映射到具体实现和验证。
6. **一致性**：问题定义、变量、假设、目标、约束、求解过程与最终结论应保持一致，不能在求解或写作阶段改变原有问题含义。
7. **可解释性**：模型中的关键变量、关系和约束应具有明确含义；复杂结构应能够说明其引入原因，而不是只以预测指标或目标值作为依据。
8. **最小充分性**：模型应在满足题目目标和验证要求的前提下保持必要的简洁性。新增变量、约束、模型或算法都应有明确作用，不能仅为增加复杂度而引入。

复杂度由问题结构、数据和验证要求决定。

### 创新的判定

建模创新应首先解决原模型中真实存在的问题，而不是单纯更换求解算法或增加模型数量。

可接受的创新通常发生在：

- 变量或状态设计；
- 模型结构；
- 目标函数或约束；
- 多模型之间的耦合关系；
- 评价与决策机制；
- 领域知识进入模型的方式。

创新需要同时满足：**有问题来源 → 有具体改动 → 改动改变模型或决策 → 能够通过实验验证**

仅调节超参数、替换求解器、增加常规后处理或增加图表，通常不能单独构成主要建模创新。

若基线模型已经充分解决题目，则不要求强行增加创新结构。

## 模型与问题复杂度

模型数量和模型复杂度不应由论文篇幅或“创新性”要求反向决定，而应由问题本身的结构决定。

一个子问题可以只需要一个模型，也可以需要多个模型，但每个模型都应承担不可替代的任务。若两个模型解决的是同一层面的同一问题，应优先比较其方法差异和证据价值，而不是机械叠加。

因此，**问题越复杂，不意味着模型越多；模型越多，也不意味着建模越充分。**


## 模型数量

每道子问题最多两个独立模型体系。允许：

- 一个主模型；
- 主模型加一个对比或验证模型；
- 两个串联模型分别完成必要阶段。

灵敏度分析、残差分析、消融实验、交叉验证和可视化属于验证方法，不单独计作模型。

物理问题按模型族而不是公式版本计数。同一物理机制、同一组核心状态变量和控制方程，在不同近似阶次、反射次数、边界简化或数值精度下的表达，属于一个模型族。例如，两光束干涉与多光束干涉若只是同一干涉机制的精度展开，计为一个模型；若引入不同传播机理或新的耦合状态方程，才另计模型。

两个模型得到相近结论并不构成删除理由。应根据研究目的、方法差异和证据价值决定是否保留。

## 组合方式

| 方式         | 条件                               | 示例                       |
| ------------ | ---------------------------------- | -------------------------- |
| 串联         | 前一模型输出是后一模型必要输入     | 需求预测 → 库存优化       |
| 并行         | 需要比较不同假设或方法             | 统计模型与机器学习模型回测 |
| 主模型加验证 | 一个模型回答问题，另一模型验证边界 | 优化模型 + 仿真验证        |

模型组合的成立条件不是“使用了多个模型”，而是模型之间存在真实的数学、数据或决策依赖。

组合后的整体模型仍应能够回答：

- 前一个模型为什么必须存在？
- 它的输出为什么必须传给后一个模型？
- 如果去掉其中一个模型，问题是否仍能被完整解决？

只有存在明确依赖时，组合才具有建模意义。


## 验证设计

验证方式根据模型选择，可包括留出集、滚动回测、残差诊断、约束可行性、最优性界、稳定性、灵敏度、消融实验和外部数据对照。检验阈值必须写明依据。

## 证据与结论

模型验证的作用不仅是证明模型“有效”，还应确定结论能够延伸到什么范围。

验证结果应分别回答：

- 模型是否满足题目约束；
- 结果是否稳定；
- 关键参数或假设变化后结论是否保持；
- 创新结构是否真正贡献了结果；
- 模型在哪些条件下可能失效。

结论强度不得超过验证证据。单次实验只能支持有限范围内的观察，对比实验可以支持相对表现，样本外或扰动实验才能进一步支持泛化与稳健性判断。

## 设计闭环

好的模型应形成：

**问题定义 → 模型抽象 → 数学表达 → 可实现求解 → 针对性验证 → 结论边界**

其中任一环节无法闭合，都应回到前一环节检查，而不是仅通过增加算法或调整参数解决。
